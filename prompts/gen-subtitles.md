你需要基于一个文案文件以及一个音频文件进行处理，并生成对应的 JSON 字幕文件。

## 你需要注意的事情

- 在进行以下工作前，你需要先使用 `nix develop` 激活工作环境。
- 对于以下工作中提及的脚本，不要检查其具体脚本代码，直接遵照流程指示操作。
- 不要创建任何新的脚本，只允许使用以下提到过的脚本；其余处理应直接进行，不依赖新建脚本。

## 工作流程

首先向用户询问以下必要信息：

1. 以哪个文案文件作为参考？
2. 需要处理哪个音频文件？
3. 工作结果的存储路径是什么？

获取以上信息后，依次进行以下操作。

### 1. 提取文案内容

运行：

`uv run utils/extract_plain_text <文案文件路径>`

将文案文件路径作为位置参数传入。

该脚本会直接将提取出的纯文本内容输出到命令行。提取出的内容作为后续字幕文本的依据。

### 2. 提取音频识别结果

运行：

`uv run utils/extract_audio_subtitles <音频文件路径>`

该脚本会直接将粗略的音频识别结果输出到命令行。输出的每一行表示从音频中识别出的一个词，格式类似：

`word: {} range: {} conf: {}`

其中：

- `word` 表示从音频中识别出的词；
- `range` 表示该词在音频中的起止时间，单位为秒；
- `conf` 表示该识别结果的置信度，越接近 `1.0` 表示越准确。

该脚本的输出用于确定实际需要制作字幕的内容范围以及字幕短句的时间范围。

### 3. 根据文案和音频识别结果划分字幕短句

只处理 `extract_audio_subtitles` 在音频中实际识别到的内容，**不要为音频中没有出现的文案内容生成字幕**。

也就是说，文案文件可能包含比当前音频更多的文本，但本次工作只处理音频中实际出现的那一部分。对于文案中没有在当前音频中出现、且在 `extract_audio_subtitles` 的识别结果中没有对应内容的部分，应直接忽略，不要将其输出到 JSON 中。

根据 `extract_audio_subtitles` 的识别结果确定本次需要处理的文案范围，再以 `extract_plain_text` 得到的文案内容作为字幕文本，将音频中实际出现的内容划分为适合字幕显示的若干短句，并参考音频识别结果中的时间信息，为每个短句确定起止时间。

字幕文本必须以文案文件中的内容为准。`extract_audio_subtitles` 的识别结果仅用于判断音频中实际说出了哪些内容以及确定时间范围，不能直接作为最终字幕文本，也不能因为识别结果中的错词、漏词或识别错误而修改文案内容。

如果音频识别结果与文案存在一定差异，应结合上下文判断其对应的文案内容，但最终输出的 `text` 必须采用文案中的原文。

划分短句时要注意字幕的可读性和长度。不要为了减少字幕条数而合并出过长的短句。应将语义自然、长度适中的片段作为一个字幕短句。例如，应优先划分为：

“并且在显示三维画面时”

“矩阵更是不可或缺的”

而不是合并为：

“并且在显示三维画面时，矩阵更是不可或缺的”

**每个短句尽量不超过 14 个字符**

短句末尾的标点符号不需要包含在 `text` 字段中。

时间范围应尽可能根据音频识别结果中对应词语的 `range` 确定，使字幕覆盖实际说出该短句的时间段。

对于文案中的 `{数学公式}` 占位：

- 如果实际音频中对应位置出现了数学公式内容，则字幕中使用 `{数学公式}` 占位；
- 即使 `extract_audio_subtitles` 对数学公式的识别结果比较杂乱，也应结合文案和对应的音频时间范围判断其是否为数学公式片段；
- 只有实际出现在当前音频中的 `{数学公式}` 才应输出；文案中存在但当前音频没有出现的数学公式应忽略；
- 只要对应的字幕短句中包含 `{数学公式}`，该短句的 `contains_math` 就设置为 `true`，否则设置为 `false`。

### 4. 输出 JSON 文件

将处理后的字幕短句以 JSON 格式输出到用户指定的工作结果存储路径中。

JSON 文件格式如下：

```json
[
    {
        "text": "第一个短句",
        "range": [0.48, 5.37],
        "contains_math": false
    },
    {
        "text": "第二个短句",
        "range": [6.0, 11.97],
        "contains_math": false
    }
]
````

其中：

* `text`：字幕短句文本，必须以 `extract_plain_text` 提取出的文案内容为准；
* `range`：该字幕短句在音频中的起止时间，参考 `extract_audio_subtitles` 的结果确定；
* `contains_math`：是否包含数学公式占位。如果该短句的文案文本中包含 `{数学公式}`，则设置为 `true`，否则设置为 `false`。

最终 JSON 中只应包含当前音频实际出现的字幕内容，不要包含音频中未出现的其余文案文本。

整个处理过程中，只允许使用 `nix develop` 激活工作环境以及上述两个已有脚本，不得创建任何新的脚本。
