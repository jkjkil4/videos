你需要基于一个文案文件以及一个音频文件进行处理，并生成对应的 JSON 字幕文件。

## 你需要注意的事情

- 在进行以下工作前，你需要先使用 `nix develop` 激活工作环境。
- 对于以下工作中提及的脚本，不要检查其具体脚本代码，直接遵照流程指示操作。
- 不要创建任何新的脚本，只允许使用以下提到过的脚本；其余处理应直接进行，不依赖新建脚本。

## 工作流程

首先向用户询问以下必要信息：

1. 以哪个文案文件作为参考？
2. 需要处理哪个音频文件？
3. 工作结果的存储路径是什么？

获取以上信息后，依次进行以下操作。

### 1. 提取文案内容

运行：

`uv run utils/extract_plain_text <文案文件路径>`

将文案文件路径作为位置参数传入。

该脚本会直接将提取出的纯文本内容输出到命令行。提取出的内容是后续字幕文本的唯一依据。

### 2. 提取音频识别结果

运行：

`uv run utils/extract_audio_subtitles <音频文件路径>`

该脚本会直接将粗略的音频识别结果输出到命令行。输出的每一行表示从音频中识别出的一个词，格式类似：

`word: {} range: {} conf: {}`

其中：

- `word` 表示从音频中识别出的词；
- `range` 表示该词在音频中的起止时间，单位为秒；
- `conf` 表示该识别结果的置信度，越接近 `1.0` 表示越准确。

该脚本的输出仅用于确定字幕短句在音频中的时间范围，不作为字幕文本的依据。

### 3. 根据文案和音频时间信息划分字幕短句

根据 `extract_plain_text` 得到的文案内容，将文案划分为适合字幕显示的若干短句，并参考 `extract_audio_subtitles` 输出的时间信息，为每个短句确定对应的起止时间。

字幕文本必须以文案文件中的内容为准。`extract_audio_subtitles` 的识别结果仅用于辅助确定时间范围，不能直接作为字幕文本，也不能因为识别结果与文案不一致而修改文案内容。

对于文案中的 `{数学公式}` 占位：

- 如果文案中出现 `{数学公式}`，则字幕中也必须保留 `{数学公式}`；
- 即使音频识别结果中的数学公式片段比较杂乱，也应根据文案判断其对应的内容，并在字幕中使用 `{数学公式}` 占位；
- 只要对应的文案短句中包含 `{数学公式}`，该短句的 `contains_math` 就设置为 `true`。

划分短句时要注意字幕的可读性和长度。不要为了减少字幕条数而合并出过长的短句。应将语义自然、长度适中的片段作为一个字幕短句。例如，应优先划分为：

“并且在显示三维画面时”

“矩阵更是不可或缺的”

而不是合并为：

“并且在显示三维画面时，矩阵更是不可或缺的”

短句末尾的标点符号不需要包含在 `text` 字段中。

时间范围应尽可能根据音频识别结果中对应词语的 `range` 确定，使字幕覆盖实际说出该短句的时间段。

### 4. 输出 JSON 文件

将处理后的字幕短句以 JSON 格式输出到用户指定的工作结果存储路径中。

JSON 文件格式如下：

```json
[
    {
        "text": "第一个短句",
        "range": [0.48, 5.37],
        "contains_math": false
    },
    {
        "text": "第二个短句",
        "range": [6.0, 11.97],
        "contains_math": false
    }
]
````

其中：

* `text`：字幕短句文本，必须以 `extract_plain_text` 提取出的文案内容为准，不使用音频识别结果作为文本依据；
* `range`：该字幕短句在音频中的起止时间，参考 `extract_audio_subtitles` 的结果确定；
* `contains_math`：是否包含数学公式占位。如果该短句的文案文本中包含 `{数学公式}`，则设置为 `true`，否则设置为 `false`。

整个处理过程中，只允许使用 `nix develop` 激活工作环境以及上述两个已有脚本，不得创建任何新的脚本。
